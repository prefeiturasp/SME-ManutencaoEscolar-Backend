apps.core.services.anexo_service

Serviços responsáveis pela gerencia dos anexos.

Este módulo centraliza a validação, preparação, armazenamento, consulta, listagem e exclusão de arquivos anexados à aplicação.

As operações de persistência são delegadas ao AnexoRepository, enquanto as validações e transformações específicas dos arquivos são realizadas neste serviço.

class apps.core.services.anexo_service.AnexoService(repository: AnexoRepository | None = None)[código-fonte]

Base: object

Centraliza as ações relacionadas aos anexos.

O serviço é responsável por validar os arquivos recebidos, preparar seus metadados e delegar as operações de persistência ao AnexoRepository.

Entre as responsabilidades aplicadas estão:

  • validação da existência do usuário responsável;

  • validação da presença, nome e tamanho do arquivo;

  • validação da extensão do arquivo;

  • identificação do tipo do anexo;

  • geração de um nome único para armazenamento;

  • identificação do tipo MIME;

  • obtenção de URL para acesso ao arquivo;

  • preparação dos dados necessários para download;

  • exclusão do anexo e do arquivo armazenado.

enviar_arquivo(arquivo: UploadedFile, id_usuario: int) → dict[str, Any][código-fonte]

Valida e persiste um arquivo anexado.

Executa o fluxo completo de envio de um arquivo: valida a existência do usuário, valida os dados do arquivo, prepara seus metadados e delega a persistência ao AnexoRepository.

A operação é executada dentro de uma transação atômica para as operações de banco de dados realizadas durante o fluxo.

Parâmetros:

  • arquivo – Arquivo que será validado e armazenado.

  • id_usuario – Identificador do usuário responsável pelo envio.

Retorna:

Dados do anexo persistido.

Levanta:

  • AnexoArquivoError – Se o arquivo informado for inválido.

  • UsuarioNaoEncontradoError – Se o usuário não existir.

validar_e_preparar_anexo(arquivo: UploadedFile, id_usuario: int | None) → dict[str, Any][código-fonte]

Valida um arquivo e prepara seus dados para persistência.

O arquivo recebido é validado quanto ao nome, tamanho e extensão. Após as validações, seus metadados são preparados para que o repositório possa persistir o anexo.

Parâmetros:

  • arquivo – Arquivo que será validado e preparado.

  • id_usuario – Identificador do usuário responsável pelo envio.

Retorna:

Metadados do anexo prontos para persistência.

Levanta:

  • AnexoArquivoError – Se o arquivo for inválido, estiver vazio, possuir uma extensão não permitida ou ultrapassar o tamanho máximo permitido de 2 MB.

  • UsuarioNaoEncontradoError – Se o usuário não existir.
